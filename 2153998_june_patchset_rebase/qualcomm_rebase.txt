CBD REMOTE BUILD — WORKFLOW REFERENCE
================================================================================

CBD is the Canonical remote kernel build system. Builds run on remote servers;
artifacts are fetched back over SSH.

PREREQUISITES
-------------
  - SSH access to cbd / cbd.kernel hosts configured in ~/.ssh/config
  - The kernel tree must have the 'cbd' remote pointing at the build system

PUSH & TRIGGER A BUILD
-----------------------
  cd ~/qualcomm/linux
  git push cbd -o native

  The push output prints the build job ID, e.g.:
    remote: kpawlak-resolute-<SHORT_SHA>-<4DIGITS>

  Full build ID format: kpawlak-resolute-<SHORT_SHA>-<4DIGITS>/arm64

CHECK BUILD STATUS
------------------
  ssh cbd.kernel ls kpawlak-resolute-<SHORT_SHA>-<4DIGITS>

  States:  QUEUED → BUILDING → BUILD-OK  (or BUILD-FAILED)
  Typical duration: 20–35 min (warm cache); up to 3h (cold cache).

  Poll loop:
    while true; do
      ssh cbd.kernel ls kpawlak-resolute-<ID> | grep arm64 | awk '{print $NF}'
      sleep 60
    done

FETCH BUILD LOG (on failure)
------------------------------
  ssh cbd log kpawlak-resolute-<ID>/arm64 > log.txt

DOWNLOAD ARTIFACTS (tarball)
------------------------------
  IMPORTANT: redirect stdout — the tarball is streamed to stdout.
  ssh cbd tarball kpawlak-resolute-<ID>/arm64 > tarball.tgz

  Typical size: ~190–200 MB.
  Contents after unpacking: arm64/*.deb (image, modules, headers, buildinfo)

FIX: wifi: ath12k: spurious WARN_ON on PREEMPT_RT (6df7255c7f33)
------------------------------------------------------------------
Symptom: on the RT kernel (7.0.0-1006-qcom-rt), dmesg flooded with:
  WARNING: drivers/net/wireless/ath/ath12k/mac.c:788
  at ath12k_mac_get_arvif+0x..., CPU#6: irq/273-ce2/...
  every ~6 seconds (firmware stats processing interval).

Root cause: WARN_ON(!rcu_read_lock_any_held()) — on PREEMPT_RT,
rcu_read_lock() does NOT disable preemption (by design), so
rcu_read_lock_any_held() fell back to !preemptible() = false even when
the lock was correctly held. False positive.

Fix: upstream commit 4498664e2d58 by Yu-Hsiang Tseng:
  "wifi: ath12k: use lockdep_assert_in_rcu_read_lock() for RCU assertions"
  Replaces WARN_ON(!rcu_read_lock_any_held()) with lockdep_assert_in_rcu_read_lock()
  which compiles out entirely without CONFIG_PROVE_RCU. Both mac.c and p2p.c.
Applied as 6df7255c7f33 (cherry-picked from qcom-next).

FIX: WiFi not scanning — regulatory domain (board config)
----------------------------------------------------------
Symptom: after fresh flash, 'nmcli device wifi list' returns empty.
Root cause: regulatory domain = 'country 00' (world roaming), all 2.4GHz
  bands flagged PASSIVE-SCAN → kernel refuses to transmit probe requests.

Fix (persistent, on the Hamoa board):
  echo "options cfg80211 ieee80211_regdom=PL" | sudo tee /etc/modprobe.d/cfg80211.conf
  (change PL to your country code)
  Reboot or: sudo modprobe -r cfg80211 && sudo modprobe cfg80211
